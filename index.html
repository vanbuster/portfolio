01

PRD Copilot

重点在生成之后。

我自己写的第一版 PRD，验收标准里有一句"用户体验流畅"。评审会上这句话根本没法讨论—— 多流畅算流畅？谁来判？后来我发现 AI 写 PRD 会成批产出这种句子， 而且版式上和真正的验收标准长得一模一样。

门 1 · 红线扫描

全文 Grep 8 条红线主表与空洞形容词扩展表。机械可判，命中即改写成量化表述再重扫。

门 2 · 结构自检

14 项逐条核对。最关键的是数据引用查验：引用调研数据必须有来源，否则强制标"假设值，需验证"。

门 3 · 独立评审

起一个独立上下文的评审子代理，只喂 PRD 全文与 rubric，不喂生成过程。

为什么门 3 必须换上下文：生成者给自己打分会分数通胀—— 它知道自己"当时是怎么想的"，会替自己把逻辑补全。一旦发生，门禁就失去公信力。
最能说明门禁有效的，是它先拒绝了一次。 第 1 轮判 §1.3 竞品断言无来源为 P0，拒绝放行；第 2 轮补样本与假设标注后 P0 清零通过。 两处非 P0 扣分未修，如实留在报告里。

放行条件是 P0 清零，不看分数。分数是连续值容易被写得好看拉高，P0 是离散硬伤。 重写最多 2 轮，修不好就交人裁决——不死循环，不谎报通过。

我明确没做的
  • 不留"待定 / TBD"——必须给建议值加假设条件。留 TBD 等于把问题推给下一个人。
  • 不做网页版的提示词。控制台一行提示词逻辑都没有，全跑 skill 本身。两套必然漂移。
  • 不做自评冒充独立评审。起不了子代理时直接标「⚠ 自评模式」，宁可难看也不假装。
02

数字分身

语气和事实，必须分开调。

常见做法是把聊天记录一股脑塞进提示词或者微调。结果两个问题耦合在一起： 语气像不像，和内容瞎不瞎编。混在同一个机制里，调好一个必然弄坏另一个。

路径 A · 人格设定

只管语气风格——怎么说话。

路径 B · 历史召回

只管不瞎编——说什么是真的。

结果

改人格不影响事实准确性，改检索不影响说话风格。

检索走三级降级：bge 语义向量 → 字符级 TF-IDF → none。 embedding 要模型服务在线，服务一挂纯 embedding 方案直接不可用； TF-IDF 零依赖可冷启动，中文短文本上效果并不差。代价是多维护一条链路， 换来可用性不依赖单点。

mood.anger_half_life_hours —— 脾气半衰期。 生气的强度每过 N 小时衰减一半。不用定时器清零，是因为情绪骤降不自然； 而半衰期只要存一个时间戳就能推算任意时刻的强度，不需要后台轮询。
检索与生成全程留 trace：本次召回用了哪个 mode、索引版本、当前状态、 候选条数与阈值过滤后条数，都可回看。做评测出身的习惯——效果不好时要能定位到哪一段出的问题， 而不是笼统地"再调调提示词"。
隐私：全链路本地运行，对话数据不出本机。后台截图只放了一张，且逐字段打码——人格引擎的配置里必然带着关于对方的推断（作息、情绪阈值这类），那些不属于我。能展示的只有架构本身。做数据相关的产品，把别人的隐私当自己的红线，是最低要求。
我明确没做的
  • 不上云。云端更快更好，但这个项目的数据性质决定了它不能上云。
  • 不做微调，走检索。微调把人格和事实焊死在一起，改一个动全身。
  • 不做多用户。它是给我自己用的，复杂度该花在人格引擎上，不是登录注册。
03

墨卦

一次典型的"可用性 ≠ 可达性"。

起点是一个开源的八字 skill，功能完整，但只有装了命令行工具的人才能用。 它的潜在用户被工具门槛挡在外面。我做的是把同样的算法换成任何人打开浏览器就能用的形态。

零构建零依赖

纯 HTML/CSS/JS，历法库 vendor 到本地。没有构建产物就没有构建失败，十年后还能打开。

BYOK 密钥模式

AI 深读用用户自带 key，只存本机。不碰用户密钥；规则引擎不依赖 AI，不填 key 照样能用。

口径严格对齐

年柱以立春为界、23:00 后日柱算次日，与原 skill 一致。同一个人两处算出不同结果，产品就废了。

有一处我做了简化并且在页面上直接标注了：梅花易数多爻动时体用取最上一动爻， 这是简化约定而非唯一解法。产品可以简化，但不能让用户以为它没被简化。
我明确没做的
  • 不做后端。没有服务器就没有用户数据，也就没有我保管不好别人密钥的可能。
  • 不让 AI 成为必需品。不填 key 也能拿到完整的规则引擎结论。
  • 不做账号、付费、留存。这是个玩具，玩具就该打开即用、关掉即走。

字节跳动

豆包大模型 · Ocean 产品团队　·　2026.06 — 至今
隐私数据拿不到，我把评测集从采集改成生成：多 Agent 造内容，双模型 8 维交叉裁决，一次通过率 90.4%，再拿裁决记录反过来改 Prompt，4 轮稳到 97%+。

2026 年 6 月进豆包大模型产品团队做评测运营。第一个卡点是数据：要测模型处理图片、录音、办公文档的能力，可这些内容都在用户手机里，隐私拿不到，评测集从第一步就停住了。

我的判断是不等数据，自己造，把难点从采集挪到质检。做法是一套多 Agent 生成工作流，按内容类型路由到图像、语音、文本三类模型；产出交给两个模型交叉打分、按 8 个维度出裁决，判定冲突就自动回流重做，同一条三次不过才转人工。人工只做兜底，不然采集省下的人力会全部贴回质检。内容一次通过率 90.4%（N=156），现在是团队构建评测集的固定一环。

跑了一段时间才发现裁决记录本身有用：不合格的原因反复集中在少数几处。我把这些 Diff 攒进一个池子，让主模型分析成因、回头改各节点的 Prompt，4 轮后 pass 率稳在 97% 以上。

之后做 Function Calling 评测集，4 个专项、1600 题、3300+ case，skill 预测工具的准确率从 66.74% 到 78.42%。call_user 这类需要人接管的场景原先只能靠人盯屏，我用 ADB 做了 Agent 自主监测，GUI 点击和文本输入自动执行，盯屏人力降到零，封装成 skill 交给团队。

学到的是：数据拿不到的时候，先别忙着找数据，先确认这个问题是不是只能靠数据解。

理想汽车

智能座舱事业部 · 智能空间产品团队　·　2025.12 — 2026.05
在理想汽车把车载 Agent 从车控扩到生活服务，用黄金 schedule diff 把「规划错」和「执行错」分开，工具调用准确率 78.3%→95.4%。

车载 Agent 原来的重心是车控。要让它接住生活服务，我先做的不是加功能，是把一次对话拆成七步来看：意图、槽位、工具、权限、调用、反馈、记忆。哪一步断了，故障长得不一样，据此定义了 4 类失败模式。用户一句话里可能塞进好几件事，我按可并发、互斥、可抢占三类关系，写了多意图仲裁规则。

评测集是我主导搭的，1000+ 用例，bad 和 good 大约 1:4，口径对齐 CSAE 团标。

最难的不是修 bug，是判断该谁修。一个 case 失败了，光看日志分不清是模型没规划对，还是工具链没执行到位。后来定了一条机械的判据：把 Planner 输出的 schedule JSON 和人工标注的黄金 schedule 做 diff。diff 命中，就是 Plan 决策错，去改 Prompt；schedule 一致却仍然执行失败，那就是工具链路的工程问题。这条线划开之后，1000+ 线上 case 才谈得上逐条归因。

半年下来，工具调用准确率从 78.3% 到 95.4%，多步任务完成率从 62% 到 85%，端到端时延从 4s 压到 2.5s，简单车控进 500ms 以内。

我从这段拿走的东西是：先把「错在哪」定义清楚，比修好其中任何一个 bug 都值钱。

千方科技

智慧交通事业部 · Omni-T 智慧高速预警　·　2025.06 — 2025.11
驻场三天、访谈八人、翻完 1200 条日志后定下 6 大类 18 子类标注规范，横评五条技术路线选定 YOLO 加大模型级联压误报，再用三按钮回流和三条漏报发现路径把指标本身管住：告警有效采纳率 60% 到 78%，首报时延 10–15 分钟压到 60 秒，试点约 300 公里、60 路摄像头。

千方是我的第一段实习，做高速公路的事件预警。上来没先写方案，去监控中心跟了三天班，访谈调度、路政、养护八个人，回来又翻了 1200 条历史事件日志。问题这才对上：调度侧有漏报，路政看到告警读不出该派谁去，上报格式每个人一套。我照这三类问题定了 6 大类 18 子类的标注规范，先让所有人说同一种话。

技术路线横评了五条，从纯 YOLO、纯 VLM 端到端，到海康一体化、TVM-R1，再到 YOLO 加大模型级联。选级联的理由不复杂：这个场景里卡住落地的不是漏检，是误报，而召回这一端 YOLO 已经保底了。所以边端跑 YOLO 管召回，云端大模型只干复核这一件事，把误报压下去。横评这一步的价值不在于最后选了哪条，在于让「为什么不选另外四条」有据可查。

指标上我改过一次口径。一开始定的是「告警有效采纳率」，后来发现这个数系统自己就能刷高——少报就行，报得越少，报对的比例越好看。于是补了两件事：给调度员做三个按钮，把反馈按语义分进三个独立 Case 池；另外开三条独立发现漏报的路径——重大事故倒查录像、相邻摄像头交叉比对、拿交警工单求差集。漏报这一侧有了自己的数，采纳率才算数。

试点铺了约 300 公里、60 路摄像头。告警有效采纳率从 60% 到 78%，首报时延从 10–15 分钟压到 60 秒。留下来的习惯是，定完一个指标先花五分钟想想它能被怎么刷；想不出来，通常说明我还没想透。
